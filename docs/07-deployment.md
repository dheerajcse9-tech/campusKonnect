# 7. Deployment Guide

This guide takes CampusKonnect from this repository to a live, HTTPS deployment that real students can use. It needs about 30–45 minutes and accounts on four free or low-cost services.

## 7.1 Target architecture

```
 Student's browser
        │  https://campuskonnect.vercel.app   (one origin for everything)
        ▼
 ┌───────────────┐   /api/*  rewrite    ┌──────────────────────┐
 │ Vercel        │ ───────────────────► │ Render web service   │
 │ React SPA     │                      │ Express API (Node 22)│
 └───────────────┘                      └─────────┬────────────┘
                                                  │
                       ┌──────────────────────────┼──────────────────────┐
                       ▼                          ▼                      ▼
                 Neon PostgreSQL          Cloudinary (images)     Resend (email)
```

**Why the `/api` rewrite?** The browser only ever talks to the Vercel domain, so the refresh cookie is a _first-party_ cookie. Safari and iOS block third-party cookies, which would otherwise log students out constantly. It also removes the need for cross-origin requests.

| Service                              | Purpose                           | Cost at MVP scale                                         |
| ------------------------------------ | --------------------------------- | --------------------------------------------------------- |
| [Vercel](https://vercel.com)         | Hosts the web app, proxies `/api` | Free (Hobby)                                              |
| [Render](https://render.com)         | Runs the API                      | Free (sleeps when idle) or Starter ≈ $7/month (always on) |
| [Neon](https://neon.tech)            | PostgreSQL                        | Free tier (0.5 GB)                                        |
| [Cloudinary](https://cloudinary.com) | Image storage, resizing, CDN      | Free tier (25 credits)                                    |
| [Resend](https://resend.com)         | Verification and reset emails     | Free tier (3,000 emails/month)                            |

This matches the cost plan in the deck: ₹0–500 for the MVP launch.

## 7.2 Step by step

### 1. Database (Neon)

1. Create a project in the **Singapore (ap-southeast-1)** region, the closest to India.
2. Copy the **direct** connection string (not the pooled one). It looks like `postgresql://user:pass@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
3. Turn on Neon's point-in-time restore or scheduled backups.

### 2. Images (Cloudinary)

1. Sign up and copy **Cloud name**, **API key** and **API secret** from the dashboard.

### 3. Email (Resend)

1. Add and verify a sending domain you own, e.g. `mail.yourcampus.in` (SPF and DKIM DNS records). Without a verified domain, emails go only to your own address and land in spam.
2. Create an API key with _sending access_.
3. Choose a sender, e.g. `CampusKonnect <no-reply@mail.yourcampus.in>`.

### 4. API (Render)

1. Render dashboard → **New → Blueprint** → select this GitHub repository. Render reads [`render.yaml`](../render.yaml).
2. Fill in the secrets it asks for:

| Variable                                                               | Value                                                                         |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `DATABASE_URL`                                                         | Neon direct connection string                                                 |
| `ALLOWED_EMAIL_DOMAINS`                                                | The college's student email domain(s), e.g. `yourcollege.edu.in`              |
| `APP_URL`, `API_URL`, `CLIENT_ORIGIN`                                  | Your Vercel URL, e.g. `https://campuskonnect.vercel.app` (all three the same) |
| `RESEND_API_KEY`, `EMAIL_FROM`                                         | From step 3                                                                   |
| `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` | From step 2                                                                   |

`JWT_ACCESS_SECRET` is generated by Render automatically.

3. Deploy. Migrations run automatically before each release (`preDeployCommand`). The server **refuses to start** if a production setting is missing or unsafe, and the deploy log says exactly which one.
4. Check `https://<service>.onrender.com/api/health` returns `{"status":"ok","database":"up"}`.

> If Render gives the service a URL other than `campuskonnect-api.onrender.com`, update the rewrite destination in [`client/vercel.json`](../client/vercel.json).

### 5. Web app (Vercel)

1. Vercel → **Add New → Project** → import this repository.
2. Set **Root Directory** to `client`. The framework (Vite), build command and output directory come from `client/vercel.json`.
3. Leave `VITE_API_URL` **unset**, because the app calls `/api` on its own origin.
4. Deploy, then open the site. You should see the landing page. `https://<your-app>.vercel.app/api/health` should return the API health JSON, which confirms the rewrite works.

### 6. First administrator

1. Register on the live site with your college email and verify it.
2. In Render → the service → **Shell**, run:
   ```bash
   node server/dist/scripts/set-role.js grant you@yourcollege.edu.in
   ```
   The grant is recorded in the audit log. Keep the number of admins small.

## 7.3 Custom domain (recommended)

Add `campuskonnect.yourcollege.in` (or your own domain) in Vercel → Domains, then update `APP_URL`, `API_URL` and `CLIENT_ORIGIN` on Render to match and redeploy.

## 7.4 Operations

| Task                  | How                                                                                                                              |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Uptime monitoring     | Point a free monitor (UptimeRobot, Better Stack) at `/api/health`                                                                |
| Logs                  | Render → Logs (structured JSON from pino, with request ids)                                                                      |
| Database backups      | Neon restore window or branches. Test a restore before launch                                                                    |
| Rotate the JWT secret | Change `JWT_ACCESS_SECRET` on Render and redeploy. Everyone stays signed in via refresh tokens; only access tokens are re-issued |
| Seed demo data        | Never on production (the seed script refuses). Use a separate Neon branch for demos                                              |
| Scale                 | Up to ~5,000 users: upgrade the Render instance and Neon plan only. No code changes needed                                       |

## 7.5 Pre-launch checklist

- [ ] `ALLOWED_EMAIL_DOMAINS` contains only the college's real student domains.
- [ ] Resend domain verified, and a test verification email arrives in Gmail and Outlook inboxes (not spam).
- [ ] Image upload works (Cloudinary URL in the listing).
- [ ] Sign-in persists after closing the browser on an iPhone (Safari) and on Android (Chrome).
- [ ] First admin created, and a test report resolved from the admin dashboard.
- [ ] Privacy policy and terms published (see [Security and privacy §6.3](06-security-and-privacy.md)).
- [ ] Backups enabled and a restore tested.
- [ ] Uptime monitor configured.
